# Exceptions

The package throws an exception whenever something can't be done as asked, 
rather than returning `false` or quietly doing something else. Most are thrown 
before anything is sent to the database, so nothing has changed.

Every exception this package throws extends 
`Programster\PgsqlObjects\Exceptions\AbstractException`, so you can catch them 
all together. Errors from the database itself come from pgsql-lib, and are 
passed on as they are.

```php
use Programster\PgsqlLib\Exceptions\ExceptionQueryError;
use Programster\PgsqlObjects\Exceptions\AbstractException;
use Programster\PgsqlObjects\Exceptions\ExceptionNoSuchIdException;

try
{
    $user = UserTable::getInstance()->load($id);
}
catch (ExceptionNoSuchIdException $exception)
{
    // there's no user with that ID, e.g. respond with a 404.
}
```


## This package's exceptions

All in the `Programster\PgsqlObjects\Exceptions` namespace.

| Exception | Thrown when |
|---|---|
| `ExceptionNoSuchIdException` | `load()` or `updateById()` is given an ID that has no row, or `batchSave()` or an [OrmTransaction](transactions.md) updates a row that no longer exists, in which case everything is rolled back. |
| `ExceptionInvalidId` | An ID can't be one of the table's IDs, e.g. it isn't a UUID, for a UUID table, or it isn't an int or a string at all. Thrown by every method that takes an ID, before any query runs, so you can tell it from `ExceptionNoSuchIdException` (see [Identifiers](identifiers.md#ids-that-arent-valid)). |
| `ExceptionUnknownColumn` | A column name isn't one of the table's, or the record class has no setter for it. This is usually a typo. Thrown by `createFromArray()`, `createFromDatabaseRow()`, a record's `update()`, `insert()`, `batchInsert()`, `updateById()`, the `...Where...()` filters and `loadRange()`'s order by column, before any query runs. |
| `ExceptionMissingRequiredData` | Something needed is missing, or would act on every row: a new record or row without a value for a required column (see [Tables and records](tables.md#required-columns-nulls-and-defaults)), a row with no ID and nothing to generate one, an empty filter for `loadWhereAnd()`, `loadWhereOr()`, `deleteWhereAnd()` or `deleteWhereOr()`, an empty list for `deleteIdsNotIn()` or `batchInsert()`, or caching an object that hasn't been saved. |
| `ExceptionObjectDeleted` | Saving or updating an object that has been deleted, including in `batchSave()` or an [OrmTransaction](transactions.md). Clone it to save it as a new row. |
| `ExceptionInvalidTransaction` (pgsql-lib's) | An [OrmTransaction](transactions.md) is used in a way it can't be: an object added both to save and to delete, tables with different connections, a table that doesn't extend `AbstractTable`, running it twice, or using after-commit callbacks inside a transaction that's already open. |
| `ExceptionUnsupportedDatabaseVersion` | Saving new objects whose IDs the database generates with `batchSave()` or an [OrmTransaction](transactions.md), on PostgreSQL older than 17. Nothing is saved. |
| `ExceptionIdGeneratedInDatabase` | A table's `generateId()` is called, but its IDs are generated by the database. Your own tables throw this from `generateId()` (see [Identifiers](identifiers.md#tables-whose-ids-the-database-generates)). |
| `ExceptionRowNotInserted` | `insert()` or a record's `save()` didn't insert its row, e.g. as a `BEFORE INSERT` trigger skipped it, so there's no row to build the object from. |
| `ExceptionWrongTable` | A table's `cacheObject()` or `batchSave()`, or an [OrmTransaction](transactions.md), is given a record that isn't one of the table's own, e.g. as the record's `getTableHandler()` returns the wrong table. Nothing is saved. |
| `ExceptionTableNotFound` | The table's columns can't be found, usually because the table doesn't exist, or `getTableName()` or `getSchemaName()` is wrong. |


## pgsql-lib's exceptions

All in the `Programster\PgsqlLib\Exceptions` namespace. These extend 
pgsql-lib's own `AbstractException`, not this package's.

| Exception | Thrown when |
|---|---|
| `ExceptionQueryError` | A query failed, e.g. a constraint was broken, or a value was the wrong type. `getErrorMessage()` has PostgreSQL's message, and `getQuery()` the query. Inside `batchSave()` or an [OrmTransaction](transactions.md), everything was rolled back. |
| `ExceptionConnectionError` | Connecting to the database failed, with PostgreSQL's reason in the message. |

`getQuery()` includes the values that were in the query, so be careful about 
logging it where those values shouldn't end up, e.g. if they include personal 
data.
