## 1. Install the package

You need PHP 8.2 or newer with the `pgsql` extension, and PostgreSQL 14 or 
newer.

```bash
composer require programster/pgsql-objects
```

This also installs [pgsql-lib](https://github.com/programster/package-pgsql-lib), 
which this package uses for its database connection and escaping.


## 2. Connect to the database

Every table class says which connection it uses, with `getDb()`. Most 
applications use one connection for every table, so create it once and share 
it, e.g. with a small class of your own:

```php
use Programster\PgsqlLib\PgSqlConnection;

class ConnectionHandler
{
    private static ?PgSqlConnection $s_db = null;


    public static function getDb() : PgSqlConnection
    {
        if (self::$s_db === null)
        {
            self::$s_db = PgSqlConnection::create(
                host: 'localhost',
                dbName: 'my_app',
                user: 'my_app',
                password: 'secret', // e.g. from your configuration, rather than in the code.
                forceNew: true,
                port: 5432
            );
        }

        return self::$s_db;
    }
}
```

`forceNew: true` always opens a new, independent connection. With `false`, 
PHP may hand back a connection the script already has open with the same 
details, which would then share its transactions and session settings, so use 
`true` unless you want that, and share a connection by passing the same 
object around instead.

A failed connection throws pgsql-lib's `ExceptionConnectionError`, with 
PostgreSQL's reason in its message.


## 3. Create the table

The package works with tables that already exist: it doesn't create them for 
you. Create them however you manage your database's schema, e.g. with 
migrations. [pgsql-migrations](https://github.com/programster/package-pgsql-migrations) 
is one way:

```php
class CreateUserTable implements \Programster\PgsqlMigrations\MigrationInterface
{
    public function up(\PgSql\Connection $dbConn) : void
    {
        $query =
            'CREATE TABLE "user" (
                "id" uuid PRIMARY KEY,
                "name" varchar(255) NOT NULL,
                "email" varchar(255) NOT NULL,
                "nickname" varchar(255),
                "created_at" timestamptz NOT NULL DEFAULT NOW()
            )';

        if (pg_query($dbConn, $query) === false)
        {
            throw new \Exception("Failed to create the user table.");
        }
    }


    public function down(\PgSql\Connection $dbConn) : void
    {
        pg_query($dbConn, 'DROP TABLE "user"');
    }
}
```

Run your migrations before using the tables. The package reads each table's 
columns from the database the first time it needs them, and then keeps them 
for as long as the table object exists.


## 4. Write the table and row classes

Each table needs a table class and a row class. For the table above:

- `UserTable` extends `AbstractUuidTable`, as its IDs are UUIDs, which the 
  package generates.
- `UserRecord` extends `AbstractTableRowObject`, with a property, getter and 
  setter for each column.

[Tables and rows](tables.md) has both classes in full, and what each method 
is for. The short version: the table class says how to connect, the table's 
name, and which columns allow null, have defaults, or are generated by the 
database. The row class says which table it belongs to, and how to get and set 
each column.


## 5. Use them

```php
use Programster\PgsqlObjects\CacheMode;

$userTable = UserTable::getInstance();

// create a new object, which gets its ID straight away, and save it.
$ada = UserRecord::createNewFromArray(['name' => 'Ada', 'email' => 'ada@example.com']);
$ada->save();

// load a row whose ID you know, e.g. from a form submission or a URL.
$user = $userTable->load('01a1bc23-57a0-7318-8532-ce41ea306b73');

// change it, and save the change straight away.
$user->update(['nickname' => 'Countess']);

// load the rows that match a filter.
$matches = $userTable->loadWhereAnd(['email' => 'ada@example.com'], CacheMode::IGNORE_CACHE);

// delete it. Its save() and update() throw from now on, so it can't come back by mistake.
$user->delete();
```

The loads that return many rows take a `CacheMode`, saying how they use the 
optional [cache](cache.md). The cache is off unless you turn it on, so 
`CacheMode::IGNORE_CACHE` is a fine choice to start with.
